0.9.0 — side-by-side view, a name for the new tab

Side-by-side view on the model Zen Browser uses, up to four panes. Setup asks what to call you. Audio keeps playing in tabs you have switched away from.

▥ Side-by-side view

Up to four pages at once. Drag a tab out of the list and drop it on the left or right edge of a page; the edge you are over lights up so there is no guessing which side it will land on. Drag the divider to change the widths, and take any pane out on its own.

A pane can never be dragged below seven percent of the window, because a page too narrow to read is worse than no split at all. A fifth pane is refused with a reason rather than becoming a sliver.

✻ Two bugs that were always there

The layout code had never been connected to the interface, so the only part of the feature that reached anyone was the sidebar app rail.

Two faults were hiding inside it the whole time, and only appeared once something actually called it: it chose the page already on screen as the second pane, so a split could show the same page twice, and it did not exclude a new tab, which has nothing to place beside one.

☀ Good morning, and good night

First-run setup now asks what to call you, and the new tab page greets you by name. The greeting is the largest thing on the page.

It also covers the whole day now. The old version had no night at all, so anyone using the browser at eleven at night was told good evening. It says good night before five and after ten.

♪ Audio that keeps playing

Switching tabs used to mute them. That is now a setting, on by default, so music and calls carry on while you read something else.

The webview stops throttling its timers to match, because a throttled page stops producing audio and the setting would otherwise look broken. Gaming Mode still silences everything, which is what it is for.

✂ First-party ad scripts

Ad code served from the site's own server is now blocked by its path, not just by its host. That covers the ad script sitting next to the site's own code, which a host-based blocker cannot see.

Every rule is anchored to a path separator. Matched as plain text, "ads.js" would also block downloads.js, uploads.js, leads.js and threads.js, which would break download buttons, upload widgets and comments across a large part of the web.

⚿ A filter exception that works

A filter of the form ||example.com/some/path did nothing, because the parser read the path as part of the domain name and could never match. That left no way to put one file back, which is exactly what is needed when a rule goes too far. Host-and-path rules now work for both blocking and allowing.

⊞ Linux

A Debian package for Ubuntu, Debian and anything else that installs .deb files, built on Linux rather than wrapped from Windows. It is published under its own update manifest, since each platform has its own.

The password vault will not store anything on Linux unless the desktop provides a real keyring such as GNOME Keyring or KWallet. It refuses to fall back to an unencrypted store, so a machine with no keyring reports the vault as unavailable rather than pretending to be protected.

✓ Verifying a download

The published hash is Base64, and the command on the download page used to print it in hex. The two could never match, which meant a genuine, untampered file looked exactly like a tampered one.

The command now converts, the file name is filled in from the live feed rather than typed in, and both copy buttons work instead of only the first.

0.8.2 — first-party ad scripts and a working filter exception

The path-based ad blocking above, plus the filter parser fix, plus a build configuration bug that would have broken every release.

⚑ The signing build was broken

The code-signing settings had never been validated, and had sat in the build configuration making every build fail. Hash algorithms and the timestamp server were in the wrong place, one option no longer exists, and another had been given values it does not accept.

That last one mattered: the values used confused the signature digest with the download hash published in the update feed, which are unrelated things.

0.7.5 — tab transfer, side panel, media controls, saved pages

The largest release so far.

⇄ Tab transfer, device to device

Send a tab to another device on your local network with no server, no account, and nothing hosted anywhere. The tab is encrypted on the sending PC with AES-256-GCM before it moves, a 100-bit pairing code authorises the transfer, and only local addresses can be reached.

▦ Side panel apps

Discord, YouTube, Spotify, Canvas, Mail and a Notes scratchpad stay open beside your tabs, each in its own sandboxed view. Only the app you are looking at is loaded.

▶ Media controls and picture in picture

A control bar for whatever the page is playing, with picture-in-picture that works from any site. The page is the source of truth, so a playlist advancing on its own is followed rather than fought.

❐ Vertical tabs and workspaces

Tabs down the left, grouped, with drag to reorder, search across all open tabs, hover preview, and a right-click menu. Workspaces keep separate sets of tabs for separate jobs.

◈ Privacy

Local phishing detection that sends nothing off the device, the Website Trust Card that says what a site can see and who is trying to track you, private windows, and Gaming Mode that suspends what you are not using.

▤ Saved pages

Keep an article to read without a connection, in a sandbox with no script execution, carrying the address and the time it was taken. Pages asking you to sign in are refused rather than saved.

Still ahead of this build

Passkeys can be created but not yet used, because Electron draws no account chooser for the assertion. A real certificate would remove the "Unknown publisher" warning, and would still not remove the SmartScreen message, which depends on downloads rather than on signing. A WebRTC limitation is described in full on the FAQ and the home page rather than being left out of the notes.
